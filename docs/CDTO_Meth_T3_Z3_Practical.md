# Аналіз процесів AS-IS / TO-BE. Виявлення неефективностей та точок покращення

*Тема 3: Бізнес-аналіз та вимоги до ІТ-продуктів · Заняття 3*

## 1. Методологія AS-IS: методи збору даних про поточний стан процесів

### 1.1. Поняття AS-IS

Модель AS-IS («як є») — опис процесу в його поточному, реальному стані. Її мета — зрозуміти, як робота відбувається насправді, виявити проблеми, неефективності й вузькі місця перед тим, як проєктувати зміни.

### 1.2. Методи збору даних

| Метод | Що дає |
| --- | --- |
| Спостереження | Реальний перебіг роботи, обхідні шляхи, приховані дії. |
| Інтерв’ю | Розуміння кроків, ролей, проблем від виконавців. |
| Аналіз документів | Регламенти, інструкції, форми, що використовуються. |
| Збір метрик | Час етапів, обсяги, частота помилок (кількісні дані). |
| Walkthrough процесу | Покроковий «прохід» процесу разом з виконавцями. |

### 1.3. Побудова моделі AS-IS

Зібрані дані оформлюють у модель (найчастіше BPMN) поточного процесу з ролями, кроками, розгалуженнями, а також фіксують метрики (час, обсяги). Модель має відображати реальність, а не ідеал.

### 1.4. «Як є» проти «як має бути за інструкцією»

Ключова вимога — моделювати процес «як є насправді», а не «як написано в інструкції». Реальний процес часто відрізняється: люди створюють обхідні шляхи, дублюють дані «для надійності», пропускають формальні кроки. Саме ці розбіжності часто вказують на справжні проблеми.

*Приклад. Інструкція каже «дані вносяться одразу в систему», а спостереження показує, що спершу записують на папір, а ввечері переносять — це вказує на незручність системи в польових умовах.*

### 1.5. Метрики процесу

Модель AS-IS доповнюють кількісними метриками, без яких неможливо довести покращення: загальний час процесу (lead time), час активної роботи vs очікування, кількість кроків і погоджень, частота помилок і переробок, обсяг (скільки разів на місяць). Ці метрики стають базовими значеннями для цільових показників TO-BE.

**Типові помилки:**

- моделювання «як має бути» замість «як є»;
- опора лише на слова без спостереження й метрик;
- ідеалізація процесу (замовчування обхідних шляхів).

*Проміжний висновок: AS-IS має чесно відображати реальність — саме розбіжність із «паперовим» процесом виявляє справжні проблеми.*

## 2. Формування моделі TO-BE: принципи реінжинірингу та вдосконалення

### 2.1. Поняття TO-BE

Модель TO-BE («як має бути») — цільовий стан процесу після вдосконалення. Вона показує, яким процес стане, і є основою для формування вимог до цифрового рішення.

### 2.2. Принципи реінжинірингу

- усунути зайві кроки, що не додають цінності;
- прибрати дублювання даних і дій;
- автоматизувати рутинні операції;
- розпаралелити послідовні дії, де це можливо;
- скоротити зайві погодження й очікування;
- запровадити єдине джерело даних.

### 2.3. Вдосконалення проти реінжинірингу

Вдосконалення (incremental) — поступові покращення наявного процесу. Реінжиніринг (radical) — переосмислення процесу «з нуля». Вибір залежить від масштабу проблем: якщо процес принципово неефективний — реінжиніринг; якщо загалом робочий — вдосконалення.

### 2.4. Критерії хорошого TO-BE

- реалістичність (здійсненно в межах обмежень ЗСУ);
- цінність (усуває виявлені проблеми, дає ефект);
- відповідність нормативам і вимогам ЗІ;
- вимірюваність покращення (цільові метрики).

### 2.5. Приклади застосування принципів

| Проблема AS-IS | Рішення у TO-BE |
| --- | --- |
| Дані дублюються у 3 журналах. | Єдиний реєстр — одне джерело істини. |
| Ручне звіряння займає дні. | Автоматичне звіряння системою. |
| Послідовні погодження тижнями. | Паралельні погодження, скорочення зайвих. |
| Помилки через ручне введення. | Валідація даних при введенні. |

**Типові помилки:**

- TO-BE як «автоматизований AS-IS» без усунення проблем;
- нереалістичний ідеал, що ігнорує обмеження;
- відсутність цільових метрик покращення.

*Проміжний висновок: TO-BE — не «той самий процес у комп’ютері», а перепроєктований процес, що усуває виявлені проблеми.*

## 3. Gap-аналіз: розриви між поточним і цільовим станом, оцінка ступеня змін

### 3.1. Поняття

Gap-аналіз (аналіз розривів) — порівняння AS-IS і TO-BE для визначення, що саме треба змінити для переходу від поточного стану до цільового. Розрив (gap) — конкретна відмінність, яку треба усунути.

### 3.2. Що аналізувати

| Аспект | Приклад розриву |
| --- | --- |
| Процеси | Ручне звіряння → автоматичне. |
| Дані | Дублювання → єдиний реєстр. |
| Ролі | Нові обов’язки, зміна відповідальності. |
| Системи | Немає ІКС → впровадження системи обліку. |
| Навички | Потреба навчання користувачів. |

### 3.3. Оцінка ступеня змін

Кожен розрив оцінюють за масштабом (дрібна зміна / суттєва / трансформація) і складністю усунення. Це дозволяє оцінити загальний масштаб трансформації й спланувати перехід.

### 3.4. Перелік змін як основа переходу

Результат gap-аналізу — структурований перелік змін (що, де, який масштаб), який стає основою для вимог, плану впровадження й оцінки ресурсів. По суті, це «міст» від аналізу до проєкту.

**Типові помилки:**

- gap-аналіз без AS-IS або без TO-BE (нема з чим порівнювати);
- облік лише процесних розривів, ігнорування даних, ролей, навичок;
- відсутність оцінки масштабу змін.

*Проміжний висновок: gap-аналіз перетворює порівняння AS-IS/TO-BE на конкретний перелік змін — основу вимог і плану впровадження.*

## 4. Виявлення неефективностей та вузьких місць у процесах підрозділу ЦТ

### 4.1. Типи неефективностей

Неефективності — кроки чи явища, що споживають ресурс, але не додають цінності. Корисно спиратися на концепцію «втрат» (lean):

- очікування (простій між етапами);
- зайві погодження й бюрократія;
- дублювання дій і даних;
- ручна праця там, де можлива автоматизація;
- переробки через помилки;
- зайве переміщення документів/інформації;
- надлишкова інформація, яку ніхто не використовує.

### 4.2. Методи виявлення

Виявляють неефективності через: аналіз часу етапів (де накопичуються затримки), теорію обмежень (пошук вузького місця), аналіз доданої цінності (чи додає крок цінність), метод «5 чому» (першопричина).

### 4.3. Вузькі місця

Вузьке місце (bottleneck) — етап, що лімітує весь процес: перед ним накопичується черга, після — простій. Саме на розшивання вузького місця спрямовують покращення в першу чергу (оптимізація інших етапів не прискорює процес).

### 4.4. Пріоритезація покращень

Виявлені точки покращення пріоритезують за цінністю та зусиллями (матриця «цінність/зусилля» з Теми 1): спершу — «швидкі перемоги» (висока цінність, малі зусилля) і розшивання вузького місця.

### 4.5. Аналіз доданої цінності

Кожен крок процесу класифікують: додає цінність (потрібен для результату), не додає, але необхідний (напр., погодження за нормативом), або не додає й не потрібен (кандидат на усунення). Мета TO-BE — максимізувати кроки, що додають цінність, і усунути безцінні.

*Приклад. Крок «внести дані в систему» додає цінність; «продублювати в зошит» — не додає й не потрібен (усунути); «погодити акт» — не додає, але необхідний.*

**Типові помилки:**

- оптимізація не-вузького місця (не прискорює процес);
- усунення симптому замість першопричини;
- покращення без оцінки цінності.

*Проміжний висновок: покращення спрямовують на вузьке місце й «швидкі перемоги», усуваючи першопричини, а не симптоми.*

## 5. Практична вправа: AS-IS/TO-BE аналіз реального процесу

**Мета вправи:** слухачі проводять повний цикл аналізу реального процесу свого підрозділу: AS-IS → виявлення неефективностей → TO-BE → gap-аналіз.

**Вихідні дані:** опис процесу (з Заняття 2 або новий); шаблони (Додатки 1–3).

**Форма роботи:** у парах/трійках, з презентацією 2–3 аналізів.

### Порядок виконання

1. Побудувати модель AS-IS процесу з метриками (час, кроки) — 25 хв.
2. Виявити неефективності та вузьке місце процесу — 20 хв.
3. Сформувати модель TO-BE, що усуває виявлені проблеми — 25 хв.
4. Провести gap-аналіз (перелік змін із масштабом) — 20 хв.
5. Презентація 2–3 аналізів із розбором — 10 хв.

### Еталонне проходження (зразок для викладача)

**AS-IS.** Облік майна: паперовий журнал → ручне звіряння (3 дні) → акт. Метрика: 3 дні, розбіжності 15%.

**Неефективності.** Вузьке місце — ручне звіряння; дублювання даних; переробки через помилки.

**TO-BE.** Єдиний реєстр → автоматичне звіряння → акт формується системою. Ціль: 1 день, розбіжності ≤ 3%.

**Gap-аналіз.** Процес (авто-звіряння), дані (єдиний реєстр), система (впровадити ІКС), навички (навчання) — суттєва трансформація.

### Методичні вказівки викладачу

Викладач перевіряє: (1) AS-IS відображає реальність (з метриками); (2) виявлено вузьке місце; (3) TO-BE усуває проблеми, а не «автоматизує AS-IS»; (4) gap-аналіз охоплює процеси, дані, ролі, системи, навички. Для розбору обирає один сильний і один поверхневий аналіз.

## Контрольні питання

1. Що таке модель AS-IS і чому її треба будувати «як є», а не «як за інструкцією»?
2. Назвіть принципи реінжинірингу при формуванні TO-BE.
3. Чим вдосконалення відрізняється від реінжинірингу?
4. Що таке gap-аналіз і які аспекти він охоплює?
5. Які типи неефективностей ви знаєте і як виявляти вузьке місце?
6. Чому не можна оптимізувати не-вузьке місце?

## Завдання для закріплення

1. Провести AS-IS/TO-BE аналіз ще одного процесу свого підрозділу.
2. Скласти перелік змін (gap-аналіз) із оцінкою масштабу для обраного процесу.
3. Підготувати обґрунтування цифрового рішення на основі виявлених проблем.

## Додаток 3. Чек-лист якості моделі TO-BE

- Усуває виявлені проблеми AS-IS (а не «автоматизує» їх).
- Реалістичний у межах обмежень ЗСУ (нормативи, ЗІ, ресурси).
- Має цільові метрики покращення.
- Прибирає дублювання, зайві кроки й погодження.
- Запроваджує єдине джерело даних.
- Відповідає вимогам захисту інформації.

## Додаток 4. «Втрати» (lean) — довідник для виявлення неефективностей

| Втрата | Приклад у процесах підрозділу |
| --- | --- |
| Очікування | Простій в очікуванні погодження. |
| Зайва обробка | Дублювання даних у кількох журналах. |
| Переробки | Виправлення помилок обліку. |
| Зайвий рух | Передавання паперів між кабінетами. |
| Надлишок інформації | Звіти, які ніхто не читає. |
| Ручна праця | Ручне звіряння замість автоматичного. |

## Додаток 5. Критерії оцінювання AS-IS/TO-BE аналізу

| Критерій | Бали | Орієнтир |
| --- | --- | --- |
| AS-IS відображає реальність (з метриками) | 0–3 | Не ідеалізовано. |
| Виявлено неефективності й вузьке місце | 0–2 | Першопричини, не симптоми. |
| TO-BE усуває проблеми, реалістичний | 0–3 | З цільовими метриками. |
| Gap-аналіз охоплює всі аспекти | 0–2 | Процеси, дані, ролі, системи, навички. |
| Разом | 0–10 | 9–10 «відмінно»; 7–8 «добре»; 5–6 «задовільно». |

## Додаток 6. Глосарій ключових термінів

- **AS-IS — **модель поточного стану процесу «як є».
- **TO-BE — **цільова модель процесу «як має бути».
- **Реінжиніринг — **радикальне переосмислення процесу.
- **Вдосконалення — **поступове покращення процесу.
- **Gap-аналіз — **аналіз розривів між AS-IS і TO-BE.
- **Вузьке місце — **етап, що лімітує весь процес.
- **Втрати (lean) — **дії, що споживають ресурс без додавання цінності.
- **Додана цінність — **внесок кроку в кінцевий корисний результат.
