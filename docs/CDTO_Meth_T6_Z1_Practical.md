# Інструменти управління проєктами та корпоративні хмарні сервіси МО

*Тема 6: Практичні цифрові інструменти та технології штучного інтелекту · Заняття 1*

## 1. Огляд і порівняння інструментів управління проєктами

### 1.1. Призначення класу інструментів

Інструменти управління проєктами оцифровують планування, завдання, беклог і контроль. Вони роблять роботу команди прозорою: видно, хто що робить, на якому етапі, що блокує. Вибір інструмента залежить від типу проєкту й команди.

### 1.2. Порівняння інструментів

| Інструмент | Сильні сторони | Коли доречний |
| --- | --- | --- |
| Jira | Гнучке управління задачами, спринти, workflow, звіти. | Складні ІТ-проєкти, agile-команди. |
| Confluence | База знань, документація, спільне редагування. | Документація й знання проєкту. |
| MS Project | Детальні Гант, ресурси, залежності. | Класичні планові проєкти, складні графіки. |
| Trello | Простота, Kanban-дошки. | Малі команди, прості задачі. |
| Asana | Задачі, проєкти, зручний інтерфейс. | Середні команди, керування задачами. |

### 1.3. Критерії вибору

- складність проєкту (простий Kanban чи повний agile);
- розмір і зрілість команди;
- потреба в документації (Confluence) чи графіках (MS Project);
- доступність і відповідність вимогам ЗІ (для роботи зі службовою інформацією).

**Типові помилки:**

- вибір «модного» інструмента без урахування задачі;
- надмірно складний інструмент для простого проєкту;
- ігнорування вимог ЗІ при виборі хмарного інструмента.

### 1.4. Екосистема інструментів

На практиці інструменти поєднують в екосистему: Jira (задачі) + Confluence (знання) + хмара (файли й комунікація). Важливо не «зоопарк» окремих інструментів, а узгоджений набір, де дані перетікають між ними. Для підрозділу ЦТ орієнтир — мінімальний достатній набір, дозволений вимогами ЗІ.

*Проміжний висновок: інструмент обирають під задачу й команду; головний критерій для ЗСУ — відповідність вимогам ЗІ.*

## 2. Практичне налаштування проєктного простору в Jira

### 2.1. Основні поняття Jira

| Поняття | Значення |
| --- | --- |
| Проєкт | Простір для роботи над ініціативою. |
| Issue (задача) | Одиниця роботи (епік, історія, задача, баг). |
| Backlog | Упорядкований перелік задач. |
| Спринт | Часовий проміжок для виконання частини задач. |
| Дошка (Kanban/Scrum) | Візуалізація потоку задач за статусами. |
| Workflow | Послідовність статусів задачі (To Do → In Progress → Done). |

### 2.2. Порядок налаштування (покроково)

1. Створити проєкт (обрати тип: Scrum або Kanban).
2. Налаштувати типи задач (епік, історія, задача, баг).
3. Наповнити беклог задачами (з User Stories, Тема 3).
4. Налаштувати дошку й статуси (workflow).
5. Для Scrum — сформувати спринт із частини беклогу.
6. Призначити виконавців і пріоритети.

### 2.3. Kanban vs Scrum

Kanban — безперервний потік задач за статусами (добре для підтримки, потоку звернень). Scrum — робота ітераціями (спринтами) з плануванням і ретроспективою (добре для розробки). Вибір залежить від характеру роботи команди.

**Типові помилки:**

- беклог без пріоритетів;
- задачі без виконавців;
- надто складний workflow для малої команди.

### 2.4. Приклад організації дошки

| Стовпець | Задачі (приклад) |
| --- | --- |
| To Do | «Налаштувати рольовий доступ», «Розробити звіт». |
| In Progress | «Реалізувати авто-звіряння» (виконавець, пріоритет High). |
| Review | «Імпорт даних» (на перевірці). |
| Done | «Створити структуру реєстру». |

### 2.5. Інтеграція Jira та Confluence

Jira керує задачами, Confluence — знаннями й документацією. Їх інтеграція дає наскрізне управління: у Confluence ведуть ТЗ, вимоги, протоколи, у Jira — виконання; сторінки Confluence можна пов’язувати із задачами Jira. Так документація й робота не «живуть окремо» (детально — у СРС).

*Проміжний висновок: Jira дає гнучке управління задачами; ключове — коректний беклог, дошка й вибір Kanban/Scrum під характер роботи.*

## 3. Корпоративні хмарні сервіси МО: Teams, OneDrive, SharePoint

### 3.1. Функціонал

| Сервіс | Призначення |
| --- | --- |
| Teams | Комунікація: чати, дзвінки, наради, канали команд. |
| OneDrive | Особисте хмарне сховище файлів. |
| SharePoint | Спільні бібліотеки документів, командні простори, портали. |

### 3.2. Спільна робота

Хмарні сервіси дозволяють спільно редагувати документи, зберігати версії, працювати над файлами одночасно, вести командні простори. Це усуває «пересилання версій поштою» й плутанину з актуальністю.

### 3.3. Правила використання та ЗІ

- використовувати лише дозволені корпоративні сервіси МО (не особисті хмари);
- дотримуватися розмежування доступу до файлів і просторів;
- не розміщувати інформацію з обмеженим доступом у сервісах, не призначених для неї;
- дотримуватися вимог ЗІ й кібергігієни (Тема 5).

Категорія інформації визначає, у якому сервісі й з яким доступом її можна обробляти. Це узгоджується з органом ЗІ.

**Типові помилки:**

- службова інформація в особистих хмарах/месенджерах;
- порушення розмежування доступу;
- обробка інформації обмеженого доступу в непризначених сервісах.

### 3.4. Практики організованої командної роботи

- канали/команди за темами (проєкт, підтримка), а не «все в одному чаті»;
- єдина структура тек (ТЗ, звіти, протоколи) — щоб файли легко знаходити;
- спільне редагування замість пересилання версій поштою;
- іменування файлів за угодою (дата, версія);
- регулярне прибирання застарілих матеріалів.

*Проміжний висновок: корпоративні хмарні сервіси прискорюють спільну роботу; їх використання суворо підпорядковане правилам ЗІ й розмежуванню доступу.*

## 4. Практична вправа: організація роботи проєктної команди в хмарному середовищі МО

**Мета вправи:** слухачі організовують робочий простір проєктної команди: проєкт у Jira (беклог, дошка) + командний простір у хмарі (документи, комунікація).

**Вихідні дані:** проєкт (система обліку майна або власний); доступ до інструментів; шаблони (Додатки 2–3).

**Форма роботи:** у малих групах (команда), з презентацією організованого простору.

### Порядок виконання

1. Створити проєкт у Jira, наповнити беклог (5–7 задач), налаштувати дошку — 20 хв.
2. Організувати командний простір у хмарі (структура документів, канал комунікації) — 15 хв.
3. Розподілити ролі й доступи (з урахуванням ЗІ) — 10 хв.
4. Презентація організованого простору 2–3 команд — 5 хв.

### Еталонне проходження (зразок для викладача)

**Jira.** Проєкт «Облік майна»; беклог з історій (авто-звіряння, звіт, доступи); Kanban-дошка To Do/In Progress/Done; виконавці й пріоритети.

**Хмара.** Командний простір: тека «ТЗ і документація», «Звіти», «Протоколи»; канал комунікації; розмежування доступу.

**ЗІ.** Службова інформація — лише в дозволених сервісах; доступ за потребою.

### Методичні вказівки викладачу

Викладач перевіряє: (1) беклог структурований і пріоритезований; (2) дошка відображає потік; (3) хмарний простір організований логічно; (4) дотримано правил ЗІ й розмежування доступу. Для розбору обирає одну сильну організацію простору.

## Додаток 1. Порівняння інструментів управління проєктами

| Інструмент | Сильні сторони | Обмеження |
| --- | --- | --- |
| Jira | Гнучкість, agile, звіти. | Складність для новачків. |

## Додаток 2. Чек-лист налаштування проєкту в Jira

- Створено проєкт (Scrum або Kanban).
- Налаштовано типи задач (епік, історія, задача, баг).
- Наповнено беклог із User Stories.
- Налаштовано дошку й статуси (workflow).
- Призначено виконавців і пріоритети.
- Для Scrum — сформовано спринт.

## Додаток 3. Правила роботи з хмарними сервісами МО

- Використовувати лише дозволені корпоративні сервіси МО.
- Дотримуватися розмежування доступу до файлів і просторів.
- Не розміщувати інформацію обмеженого доступу в непризначених сервісах.
- Узгоджувати категорію інформації та сервіс з органом ЗІ.
- Дотримуватися вимог кібергігієни (Тема 5).

## Додаток 4. Критерії оцінювання організації простору

| Критерій | Бали | Орієнтир |
| --- | --- | --- |
| Беклог структурований і пріоритезований | 0–3 | Задачі з пріоритетами й виконавцями. |
| Дошка відображає потік роботи | 0–2 | Коректні статуси. |
| Хмарний простір організований логічно | 0–3 | Зрозуміла структура. |
| Дотримано правил ЗІ й доступу | 0–2 | Розмежування доступу. |
| Разом | 0–10 | 9–10 «відмінно»; 7–8 «добре»; 5–6 «задовільно». |

## Додаток 5. Глосарій ключових термінів

- **Jira — **інструмент управління задачами й проєктами.
- **Backlog — **упорядкований перелік задач.
- **Спринт — **ітерація виконання задач у Scrum.
- **Kanban — **управління безперервним потоком задач.
- **Scrum — **управління ітераціями (спринтами).
- **Workflow — **послідовність статусів задачі.
- **Confluence — **інструмент бази знань і документації.
- **Teams / OneDrive / SharePoint — **сервіси комунікації, сховища та спільної роботи.
- **Розмежування доступу — **надання доступу лише за потребою.
