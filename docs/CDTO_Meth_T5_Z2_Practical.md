# Підготовка аналітичних матеріалів та розробка форматів звітності

*Тема 5: Документування, захист інформації та ефективні презентації · Заняття 2*

## 1. Структура та правила підготовки аналітичної записки: від збору даних до висновків і пропозицій

### 1.1. Призначення

Аналітична записка перетворює дані на обґрунтоване рішення. Вона веде читача логічним шляхом: проблема → дані → аналіз → варіанти → рекомендація.

### 1.2. Структура

1. Проблема / привід: що аналізуємо й навіщо.
2. Дані: зібрана фактична інформація (з джерелами).
3. Аналіз: що дані означають (причини, тенденції, наслідки).
4. Варіанти: 2–3 альтернативи з перевагами й недоліками.
5. Оцінка варіантів за критеріями (цінність, вартість, строк, ризик).
6. Висновки й рекомендація: обґрунтований вибір і наступні кроки.

### 1.3. Від даних до висновків

Ключова навичка — не «викласти дані», а зробити з них висновок. Дані відповідають на «що є», аналіз — на «що це означає», рекомендація — на «що робити». Записка без висновку — це не аналітика, а звіт про дані.

### 1.4. Правила підготовки

- спиратися на факти й дані, а не на враження;
- відокремлювати факти від припущень та оцінок;
- писати стисло, мовою рішення (для командування);
- подавати кілька варіантів, а не єдиний «очевидний»;
- починати з головного (висновок — на початку, деталі — далі).

*Приклад. Замість «за місяць зафіксовано 120 звернень, з них 48…» → «Головна проблема системи — складність звітів (40% звернень); рекомендуємо спростити майстер звіту». Деталі — нижче.*

**Типові помилки:**

- виклад даних без висновків і рекомендації;
- єдиний варіант без альтернатив;
- змішування фактів, припущень і оцінок;
- обсяг, за яким не видно головного.

### 1.5. «Погана» і «добра» записка: порівняння

| Погана записка | Добра записка |
| --- | --- |
| Починається з довгого переліку даних. | Починається з головного висновку й рекомендації. |
| Немає рекомендації («ось дані, вирішуйте»). | Чітка рекомендація з обґрунтуванням. |
| Один «очевидний» варіант. | 2–3 варіанти з оцінкою. |
| Факти й думки перемішані. | Факти, припущення й оцінки розділені. |
| Багато сторінок, головне «загублене». | Стисло; деталі — у додатках. |

*Проміжний висновок: аналітична записка веде від даних до рекомендації; її сила — у висновку, а не в обсязі даних.*

## 2. Типи та формати звітності для різних категорій стейкхолдерів

### 2.1. Рівні звітності

Звітність адаптують до рівня стейкхолдера — різним аудиторіям потрібен різний рівень деталізації й горизонт:

| Рівень | Аудиторія / горизонт | Зміст |
| --- | --- | --- |
| Оперативна | Виконавці; день/тиждень. | Деталі, поточні показники, інциденти. |
| Тактична | Керівники середньої ланки; місяць/квартал. | Тенденції, виконання планів, проблеми. |
| Стратегічна | Командування; квартал/рік. | Ключові підсумки, ефект, рішення. |

### 2.2. Принцип піраміди

Що вищий рівень, то стисліший і узагальненіший звіт: командуванню — головне й рекомендації (одна сторінка), виконавцям — деталі. Помилка — давати командуванню операційні деталі, а виконавцям — лише узагальнення.

### 2.3. Регулярність і формат

Звітність буває регулярна (періодичні звіти) і разова (за подією). Формат уніфікують (шаблон), щоб звіти були зіставними в часі й швидко читалися.

**Типові помилки:**

- однаковий звіт для всіх рівнів;
- операційні деталі в стратегічному звіті;
- відсутність уніфікованого формату.

*Проміжний висновок: звітність адаптують до рівня стейкхолдера — від деталей (оперативна) до підсумків і рішень (стратегічна).*

## 3. Принципи та інструменти візуалізації даних: інфографіка, дашборди, таблиці

### 3.1. Навіщо візуалізація

Візуалізація робить дані зрозумілими швидше за текст: одна діаграма показує тенденцію, яку в тексті довелося б довго описувати. Мета візуалізації — зрозумілість, а не декоративність.

### 3.2. Що коли застосовувати

| Інструмент | Коли | Приклад |
| --- | --- | --- |
| Таблиця | Точні значення, порівняння по рядках. | Показники по підрозділах. |
| Лінійна діаграма | Тенденція в часі. | Adoption по місяцях. |
| Стовпчикова | Порівняння категорій. | Звернення за типами. |
| Кругова | Частки цілого (небагато категорій). | Структура витрат. |
| Дашборд | Кілька показників разом, моніторинг. | Стан впровадження ІКС. |
| Інфографіка | Наочне подання ідеї/процесу. | Схема процесу для командування. |

### 3.3. Принципи хорошої візуалізації

- один графік — одна думка;
- прибрати зайве («чорнило», що не несе інформації);
- чіткі підписи осей, одиниці, джерело;
- коректні шкали (не спотворювати дані);
- колір — для сенсу, а не для прикраси.

### 3.4. Чесність візуалізації

Візуалізація не повинна вводити в оману: обрізана вісь, некоректний масштаб чи вибіркові дані спотворюють картину. Офіцер ЦТ подає дані чесно — маніпуляція графіками підриває довіру й веде до хибних рішень.

**Типові помилки:**

- графік «для краси» без думки;
- спотворення шкал (обрізана вісь);
- перевантаження деталями; відсутність підписів і джерела.

### 3.5. Приклад вибору візуалізації

Для однакових даних правильний вибір графіка залежить від того, що треба показати:

| Що показати | Правильний вибір |
| --- | --- |
| Як adoption зростав за півроку | Лінійна діаграма (тренд у часі). |
| Порівняти adoption 5 підрозділів | Стовпчикова діаграма. |
| Структуру звернень за типами | Кругова (якщо категорій мало) або стовпчикова. |
| Точні значення показників | Таблиця. |
| Загальний стан впровадження | Дашборд (кілька показників разом). |

*Проміжний висновок: візуалізація служить зрозумілості й чесності; один графік — одна думка, без спотворень і зайвого.*

## 4. Практична вправа: підготовка аналітичної записки за реальним кейсом підрозділу ЦТ

**Мета вправи:** слухачі готують повну аналітичну записку за наданим кейсом: від даних до рекомендації, з візуалізацією ключових показників.

**Вихідні дані:** кейс із даними (напр., статистика використання ІКС); шаблони (Додатки 1–3).

**Форма роботи:** у парах, з презентацією 2–3 записок.

### Порядок виконання

1. Опрацювати дані кейсу, виділити ключові факти — 20 хв.
2. Провести аналіз (причини, тенденції, наслідки) — 25 хв.
3. Сформувати варіанти й рекомендацію — 25 хв.
4. Підготувати 1–2 візуалізації ключових показників — 20 хв.
5. Оформити записку за структурою; презентація 2–3 робіт — 30 хв.

### Еталонне проходження (зразок для викладача)

**Проблема.** Низький adoption системи обліку в частині підрозділів.

**Дані.** Adoption 60% загалом; у 3 підрозділах — 20%; 48 звернень/міс про складність звіту.

**Аналіз.** Проблемний сегмент (3 підрозділи) + продуктова проблема (звіт). Причина низького adoption — брак навчання + складність.

**Варіанти.** А — цільове навчання сегмента + спрощення звіту; Б — лише навчання; В — лише спрощення.

**Рекомендація.** Варіант А (комплексний): очікуваний adoption ≥ 85%. Візуалізація — стовпчикова діаграма adoption по підрозділах.

### Методичні вказівки викладачу

Викладач перевіряє: (1) записка веде від даних до рекомендації; (2) є альтернативи; (3) факти відокремлені від оцінок; (4) візуалізація коректна й доречна. Для розбору обирає одну сильну й одну «звіт без висновку».

## Контрольні питання

1. Яка структура аналітичної записки? Чим висновок відрізняється від даних?
2. Які рівні звітності й чим вони різняться за деталізацією?
3. Який принцип адаптації звіту до рівня стейкхолдера?
4. Коли яку візуалізацію застосовувати?
5. Які принципи чесної та зрозумілої візуалізації?

## Завдання для закріплення

1. Підготувати аналітичну записку за реальними даними свого підрозділу.
2. Розробити шаблон регулярного звіту для командування (стратегічний рівень).
3. Підготувати дашборд ключових показників однієї ІКС.

- Один графік — одна думка.

- Прибрати зайве; чіткі підписи, одиниці, джерело.
- Коректні шкали — не спотворювати дані.
- Колір — для сенсу, а не прикраси.
- Мета — зрозумілість, а не декоративність.

## Додаток 4. Критерії оцінювання аналітичної записки

| Критерій | Бали | Орієнтир |
| --- | --- | --- |
| Логіка: від даних до рекомендації | 0–3 | Є висновок і рекомендація. |
| Альтернативи та їх оцінка | 0–2 | 2–3 варіанти. |

| Разом | 0–10 | 9–10 «відмінно»; 7–8 «добре»; 5–6 «задовільно». |

## Додаток 5. Глосарій ключових термінів

- **Аналітична записка — **структурований документ аналізу з рекомендацією.
- **Оперативна звітність — **детальна звітність поточного рівня.
- **Тактична звітність — **звітність середнього рівня з трендами.
- **Стратегічна звітність — **стисла звітність для командування.
- **Дашборд — **панель ключових показників для моніторингу.
- **Інфографіка — **наочне графічне подання інформації.
- **Чесність візуалізації — **подання даних без спотворень.
