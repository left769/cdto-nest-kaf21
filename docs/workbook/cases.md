# Легенда та кейси

## Легенда

Ви — команда підрозділу цифрової трансформації **умовної військової частини**. Командир поставив завдання: знайти процес, який забирає в особового складу найбільше часу на паперову роботу, і за курс підготувати рішення — від цілей і плану до технічного завдання та робочого прототипу, який можна показати командуванню.

Частина, підрозділи, люди й цифри в кейсах вигадані. Коли бракує даних, команда сама вигадує правдоподібні вихідні дані й фіксує їх як **припущення** (вони знадобляться в RAID-log на кроці 3).

## Як обрати кейс

1. Кожна команда обирає один кейс зі списку нижче; двом командам один кейс не дають.
2. Кейс обирають на кроці 1 і фіксують у статуті на кроці 2; до кінця курсу він не змінюється. Змінювати можна лише обсяг — через запит на зміну (крок 9).
3. Масштабуйте до MVP: прототип має вміщатися у 5–8 User Stories категорії Must.

## Зразок у зошиті: облік майна

Цей приклад проходить через заняття курсу і розібраний у кожному кроці зошита. Команди його не обирають.

| | |
| --- | --- |
| **Біль** | Облік майна ведуть у паперових журналах, інвентаризація триває 3 дні, розбіжності між обліком і фактом шукають уручну. |
| **Користувачі** | Відповідальний за облік, матеріально відповідальні особи, командир. |
| **Ціль** | Частина веде облік майна без паперу, інвентаризація — не довше 1 дня. |

## Кейси для команд

### Кейс 1. Електронна стройова записка

| | |
| --- | --- |
| **Біль** | Щоранку командири підрозділів подають наявність особового складу паперовими записками або в месенджерах; штаб зводить дані вручну, звіт готовий не раніше обіду, цифри часто не сходяться. |
| **Користувачі** | Командир підрозділу, черговий штабу, начальник штабу. |
| **Зараз** | Паперова форма, дзвінки, переписування в загальну таблицю. |
| **Підказка до MVP** | Подання наявності підрозділом за категоріями (у строю, у відрядженні, на лікуванні тощо), автоматичне зведення по частині, контроль, хто ще не подав. |

### Кейс 2. Заявки на ремонт техніки

| | |
| --- | --- |
| **Біль** | Заявки на ремонт подають усно або паперовим рапортом; ремонтний підрозділ не бачить загальної черги, пріоритети визначають «хто голосніше», стан ремонту невідомий заявнику. |
| **Користувачі** | Водій / відповідальний за техніку, начальник ремонтного підрозділу, заступник командира з озброєння. |
| **Зараз** | Рапорти, журнал у ремонтному підрозділі, телефонні уточнення. |
| **Підказка до MVP** | Подання заявки, пріоритезація за критичністю, черга й статуси ремонту, звіт про техніку в ремонті. |

### Кейс 3. Облік допусків і навчань

| | |
| --- | --- |
| **Біль** | Ніхто не бачить, у кого спливає строк допуску чи посвідчення (водійські категорії, допуски до роботи з технікою, курси); про прострочення дізнаються під час перевірок. |
| **Користувачі** | Кадровий орган частини, командири підрозділів, сам військовослужбовець. |
| **Зараз** | Розрізнені таблиці в різних посадових осіб. |
| **Підказка до MVP** | Реєстр допусків із датами дії, нагадування про завершення строку, зведення по підрозділу, план навчань. |

### Кейс 4. Служба підтримки ІКС

| | |
| --- | --- |
| **Біль** | Користувачі інформаційних систем частини звертаються за допомогою дзвінками й повідомленнями; звернення губляться, повторювані проблеми не видно, неможливо оцінити навантаження. |
| **Користувачі** | Користувач ІКС, фахівець Product Support, начальник підрозділу ЦТ. |
| **Зараз** | Особисті месенджери, записи в зошиті. |
| **Підказка до MVP** | Реєстрація звернення, категорія й пріоритет, призначення виконавця, статуси, звіт про повторювані проблеми (зв’язок із темою 3, заняття 5). |

### Кейс 5. Видача засобів зв’язку

| | |
| --- | --- |
| **Біль** | Радіостанції, акумулятори й гарнітури видають під підпис у журналі; незрозуміло, що де перебуває, хто що не повернув і які акумулятори вже вичерпали ресурс. |
| **Користувачі** | Начальник зв’язку, відповідальний за видачу, командир підрозділу. |
| **Зараз** | Паперовий журнал видачі, періодичні перевірки. |
| **Підказка до MVP** | Реєстр засобів, видача й повернення, хто що має на руках, прострочене повернення, облік циклів заряджання акумуляторів. |
