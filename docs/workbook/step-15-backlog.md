## Навіщо

На цьому кроці User Stories з кроку 10 стають робочим беклогом, а команда вирішує, **що саме увійде в MVP**. Саме цей обсяг на кроці 16 ШІ реалізує в прототипі.

**На вході:** вимоги (крок 10), бюджет (крок 5).

**Інструмент:** Jira, якщо вона доступна на занятті. Якщо ні — будь-яка дошка з колонками: Trello, Planner, таблиця або навіть дошка зі стікерами. Головне — беклог, пріоритети й обсяг MVP, а не інструмент. Службових даних на зовнішні дошки не вносьте.

## Шаблон

```markdown title="15-beklog.md"
# Беклог і обсяг MVP

**Інструмент:** [Jira / інша дошка] · **Тип дошки:** Scrum / Kanban — [чому]

## 1. Епіки та історії

| Епік | Історія (ID і назва) | Пріоритет | Оцінка | У MVP? |
| --- | --- | --- | --- | --- |
| | US-01 … | Must | | так |

## 2. Обсяг MVP

- **Входить:** [ID історій]
- **Не входить і чому:** [ID історій — причина]

## 3. Дошка

| To Do | In Progress | Review | Done |
| --- | --- | --- | --- |
| | | | |

## 4. Документація проєкту

| Розділ (сторінка / тека) | Що містить | Хто веде | Хто має доступ |
| --- | --- | --- | --- |
| | | | |
```

## Підказки

| Поле | Як заповнити | Типова помилка |
| --- | --- | --- |
| Епіки | 2–4 великі функціональні області, кожна з кількома історіями. | Епік з однієї історії. |
| Пріоритет | MoSCoW з кроку 10; у MVP — усі Must, Should — лише якщо не ускладнюють Must. | Усе позначено Must. |
| Обсяг MVP | 5–8 історій. Пояснення, чому історія не входить, — теж результат. | MVP «на всю систему». |
| Тип дошки | Scrum — для розробки з цілями спринту, Kanban — для потоку задач. | Вибір без пояснення. |
| Документація | Структура, у якій зберігатимете файли кроків 1–18, і правила доступу. | Файли в особистих месенджерах. |

## Зразок: облік майна

??? example "Розгорнути зразок"

    | Епік | Історія | Пріоритет | У MVP? |
    | --- | --- | --- | --- |
    | Реєстр майна | US-01 Внесення позиції | Must | так |
    | Реєстр майна | US-06 Пошук і фільтр | Should | так |
    | Інвентаризація | US-02 Авто-звіряння | Must | так |
    | Інвентаризація | US-03 Акт розбіжностей | Must | так |
    | Інвентаризація | US-04 Затвердження акта командиром | Must | так |
    | Звітність | US-05 Зведення для командира | Should | так |
    | Звітність | US-07 Експорт у CSV | Could | ні — не впливає на KR |

    **Дошка:** Scrum, спринт MVP — 2 тижні.

    **Документація:** теки «01–07 Управління», «08–10 Аналіз», «11–18 Впровадження»; доступ — лише команда й викладач.

## Чек-лист самоперевірки

- Усі історії з кроку 10 розподілено за епіками.
- Обсяг MVP визначено: 5–8 історій, усі Must входять.
- Для кожної історії поза MVP вказано причину.
- Тип дошки обрано й обґрунтовано.
- Визначено структуру документації та правила доступу.

!!! tip "Що з цього візьме ШІ на кроці 16"
    Обсяг MVP. Перед кроком 16 позначте в `10-vymohy.md` історії поза MVP як Won't (цього разу) — тоді ШІ не витрачатиме зусиль на те, що ви свідомо відклали.
