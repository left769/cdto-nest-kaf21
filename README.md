# Навчальний портал CDTO

Навчальні матеріали курсу цифрової трансформації для офіцерів CDTO. Сайт створюється з Markdown-документів за допомогою MkDocs Material.

- **7 тематичних напрямів**
- **28 навчальних занять**
- [Перейти до програми курсу](docs/program.md)

## Локальний запуск

Потрібен Python 3.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
mkdocs serve
```

Відкрийте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для production-збірки виконайте:

```bash
mkdocs build --strict
```

Зібраний сайт буде у каталозі `site/`.

## Структура

- `mkdocs.yml` — тема, розширення Markdown і навігація.
- `docs/index.md` — головна сторінка порталу.
- `docs/program.md` — текстовий перелік занять (у збірку сайту не входить, каталог — на головній).
- `docs/CDTO_Meth_*.md` — матеріали навчальних занять.
- `docs/stylesheets/extra.css` — стилі порталу.
- `docs/javascripts/` — оформлення сторінок занять (`lesson.js`) і логіка тестів (`quiz.js`).
- `quizzes/` — тести «Перевірте себе» до кожного заняття.
- `hooks/quiz.py` — вбудовує тест у сторінку заняття під час збирання.
- `docs/stylesheets/mod-theme.css` — тема в стилістиці mod.gov.ua (шрифт e-Ukraine у `docs/assets/fonts/`).
- `overrides/partials/header.html` — шапка з логотипами й назвою курсу (назва — `extra.course` у `mkdocs.yml`).
- `docs/contacts.md` — сторінка контактів (посилання в шапці).
- `docs/workbook/` — робочий зошит: наскрізний проєкт із 18 кроків.
- `hooks/workbook.py` — додає на сторінку заняття посилання на його крок зошита.

Щоб оновити матеріали, змініть відповідний Markdown-файл у `docs/`. Під час `mkdocs serve` сайт автоматично оновиться.

## Тести «Перевірте себе»

Після основного матеріалу кожного заняття (перед «Контрольними питаннями») стоїть тест для самоперевірки. Відповіді перевіряються одразу на сторінці й нікуди не надсилаються. Результат зберігається лише в браузері слухача, а на головній біля складених занять з’являється позначка ✓.

Тест до заняття `docs/<назва>.md` лежить у `quizzes/<назва>.md`. Формат:

```markdown
# Тест · Назва заняття
Прохідний бал: 75

## Текст питання
+ правильна відповідь
- хибна відповідь
- хибна відповідь
> Пояснення, яке слухач побачить після перевірки.
```

- `+` — правильна відповідь, `-` — хибна. Кілька рядків `+` в одному питанні роблять його питанням із кількома правильними відповідями.
- Порядок варіантів на сторінці перемішується, тож правильну відповідь можна писати першою.
- Правильна відповідь не повинна бути помітно довшою чи детальнішою за хибні, інакше її вгадують без знання матеріалу. Подробиці краще переносити в пояснення (`>`).
- Якщо файлу тесту немає, сторінка заняття показується без тесту.
- Помилки формату (питання без правильної відповіді тощо) показуються як попередження під час `mkdocs build --strict`.

Чернетки питань складено за матеріалами занять; перед використанням їх варто вичитати викладачам відповідних тем.

## Робочий зошит

Наскрізний командний проєкт: по одному кроку на кожне практичне заняття, наприкінці — прототип (MVP) за допомогою ШІ й захист. Сторінки лежать у `docs/workbook/`: огляд (`index.md`), легенда й кейси (`cases.md`) і кроки `step-NN-*.md`.

Кожен крок починається з метаданих:

```markdown
---
lesson: CDTO_Meth_T2_Z2_Practical   # файл заняття без .md
step: 2
summary: Один рядок — з’являється в блоці на сторінці заняття.
---
```

За полем `lesson` збирання саме додає на сторінку заняття блок «Наскрізний проєкт: крок N» перед тестом. Одне заняття — один крок. Новий крок також треба додати в розділ «Робочий зошит» навігації в `mkdocs.yml` і в таблицю кроків в `docs/workbook/index.md`.

Кейси навчальні й вигадані: на кроці 16 документи команд передаються зовнішньому сервісу ШІ, тому реальних службових даних у них бути не повинно.
